Review notes · what is real, what is simulated

Fields. Every fact shown exists on today's Job/BrokerStatus contract: state (reserved/running/finishing), weight, forced, admitted_by_backfill, attempt, admitted_at, started_at, process pid, free_memory_at_admission_bytes, the active job's checkpointed ResourceSummary (CPU time, peak CPU %, peak combined RSS, samples, completeness), cancellation progress and broker termination; for queued jobs queue_position, priority, queued_at, runner_connected, grace_remaining, blocked_reason and backfill_bypass_count; and status capacity, occupied, queue mode/state, head reason, free memory and load averages. No completion percentage, ETA or predicted start time is shown: the broker does not predict them.

Running. Elapsed is measured from started_at (root process start). A reserved job without started_at shows “awaiting launch” timed from admitted_at instead; there is no fabricated runtime. Bars are scaled to the longest elapsed among active rows and drawn open-ended (dotted tail) because the job has not finished. Resource figures are the last broker checkpoint and may lag; missing measurements read “not recorded”, never zero.

Queued. Order is (priority ascending, then queue sequence): lower integers run first, default 1337, and priority never preempts reserved or running work. Position is order, not a start time; resource checks use the last live sample and admission is decided by the broker at each decision. Move to Front/Back reorders and, like MoveJob, clamps the job's priority to its new neighbour when needed — the simulation shows that clamp. Priority editing exists as an API (SetJobPriority) but is not a monitor control today, so it is shown read-only.

Controls. Pause/Resume, Move to Front/Back, Force Start… and Cancel… mirror ControlAction; force-start and every cancellation show the incumbent confirmation text. The simulation updates local state only; it never admits jobs on its own, so after a cancel or resume the queue head is shown as admissible “at the next broker decision”. “Draining” is not a broker state: a paused queue with running work is shown as Paused, with reservations continuing.

Truthfulness states. Broker unavailable dims the lists, freezes clocks at the last update, shows the queue state as Unknown, and disables every control. Disconnected runners, oversized jobs, cancellation in progress and broker termination are row-level warnings and are collected under the Attention tab. The 1000 × 650 viewport is illustrative, as in the finished design; the Window selector demonstrates narrow layouts.
